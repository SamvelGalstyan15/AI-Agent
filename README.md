# 🤖 AI Agent: Автоматическая классификация и семантический маппинг номенклатуры

Промышленный ИИ-агент на базе локальной LLM (**Qwen 2.5**) и векторного поиска (**LaBSE + ChromaDB**) для автоматизации процесса разбора накладных поставщиков и их бесшовной интеграции со складским учетом системы **iiko**.

Сервис работает полностью локально, гарантирует стопроцентную конфиденциальность коммерческих данных и разворачивается в виде production-ready бэкенда на фреймворке **FastAPI**.

---

## 💡 Основной функционал и архитектурный паттерн

Проект реализует продвинутую гибридную логику классификации данных на стыке NLP, векторного поиска и больших языковых моделей (LLM):

1. **Семантический маппинг (Vector Search):** Входящая «грязная» строка из накладной векторизуется мультиязычной моделью `LaBSE` и сравнивается с существующей базой товаров в `ChromaDB`. Система рассчитывает коэффициент уверенности (`confidence_score`). Если товар найден с высокой точностью, агент мгновенно производит стыковку.
2. **Локальный LLM-Агент (Structured Extraction):** Если точного совпадения в базе нет, позиция передается локальной языковой модели `Qwen 2.5`. Агент выполняет *zero-shot* извлечение характеристик (чистое имя, бренд, объем/вес, единицы измерения, процент жирности) и автоматически подбирает наиболее логичную категорию номенклатуры (включая полную поддержку локализованных групп, например, на армянском языке: *«Ջրեղեն»*, *«Կաթնամթերք»*).
3. **Structured JSON Output:** На выходе агент гарантированно отдает строго валидный JSON-объект, полностью готовый к отправке в REST API iiko.

---

## 🛠 Стек технологий

* **LLM Core:** Hugging Face Transformers, Qwen 2.5 (Instruct)
* **Vector DB & Embeddings:** ChromaDB (Persistent Storage), SentenceTransformers (LaBSE)
* **Backend API:** FastAPI, Uvicorn, Pydantic
* **DevOps:** Docker (slim-image), Компиляторы C++ (build-essential, g++, cmake)
* **Data Science & Client:** Python, Pandas, Requests, PyTorch, Tqdm, Openpyxl
* **Разработка и логи:** Изоляция памяти (`gc.collect`, `torch.cuda.empty_cache`), принудительная фильтрация предупреждений.

## 🚀 Быстрый запуск

Вы можете запустить проект стандартным способом в локальном Python-окружении или развернуть изолированный микросервис одной командой с помощью **Docker**.

### Вариант 1: Развертывание через Docker (Рекомендуемый)

Этот способ не требует ручной установки Python-зависимостей и системных компиляторов на ваш компьютер. Всё необходимое соберется автоматически внутри изолированного контейнера.

1. Убедитесь, что в корне проекта создана папка с векторной базой данных `./real_iiko_db` (генерируется один раз через ноутбук `Agent.ipynb`).
2. Соберите и запустите Docker-контейнер в фоновом режиме:
   ```bash
   docker build -t ai-nomenclature-matcher .
   docker run -d -p 8000:8000 --name ai_matcher_container -v ./real_iiko_db:/app/real_iiko_db ai-nomenclature-matcher
   ```
   *Контейнер автоматически установит системные компиляторы для ChromaDB, развернет FastAPI и откроет порт `8000` для приема внешних запросов.*

3. Перейдите к **Шагу 3** для запуска клиентской обработки файлов.

---

### Вариант 2: Локальный запуск (Классический)

* **Шаг 1: Установка зависимостей**
  Склонируйте репозиторий и установите пакеты из файла манифеста:
  ```bash
  pip install -r requirements.txt
  ```

* **Шаг 2: Инициализация базы данных (Запускается один раз)**
  1. Положите ваш эталонный номенклатурный справочник ресторанного учета в корень проекта под именем **`Товары iiko.xlsx`**.
  2. Откройте интерактивный ноутбук **`Agent.ipynb`** в вашей среде разработки (Jupyter Lab, VS Code) и запустите все ячейки по порядку (**Run All**).
  3. Скрипт обработает файл, векторизует названия товаров через модель `LaBSE` и создаст локальную векторную базу данных в папке `./real_iiko_db`.

* **Шаг 3: Запуск фонового веб-сервиса (Бэкенд)**
  Если вы не используете Docker, запустите локальный API-сервер вручную:
  ```bash
  uvicorn api:app --host 0.0.0.0 --port 8000 --reload
  ```

---

### Шаг 3: Пакетная обработка новых накладных (Клиентская часть)

Независимо от того, как запущен бэкенд (локально или в Docker), процесс обработки накладных остается прежним:

1. Положите файл с новой накладной от поставщика в корень проекта под именем **`invoice.xlsx`** (в нем должна быть обязательная колонка *«Наименование»*).
2. Запустите клиентский скрипт автоматизации:
   ```bash
   python excel_process.py
   ```
3. Скрипт построчно отправит все позиции на сервер (порт `8000`), рассчитает уровень уверенности совпадения и сгенерирует готовый файл **`invoice_processed.xlsx`** со всеми проставленными категориями, артикулами и комментариями ИИ-агента.

## 📁 Структура проекта

* `Agent.ipynb` — Интерактивный Jupyter Ноутбук. Использовался как исследовательская песочница (R&D) для экспериментов, подбора параметров поиска, отладки системных промптов и первичного наполнения векторной базы ChromaDB.
* `api.py` — Production бэкенд на **FastAPI**. Реализует REST API эндпоинт `/predict` для быстрого семантического поиска аналогов номенклатуры.
* `Dockerfile` — Инструкция автоматической сборки изолированного Linux-образа. Конфигурирует сборку системных C++ зависимостей для корректной работы векторного движка базы данных на удаленном сервере.
* `excel_process.py` — Автономный скрипт-обработчик для построчного парсинга файлов `invoice.xlsx`, выполнения сетевых запросов к API и автоматического формирования обогащенных таблиц.
* `requirements.txt` — Список зависимостей проекта с фиксированными именами библиотек.
* `LICENSE` — Файл лицензии проекта.
* `.gitignore` — Конфигурация для исключения локальных весов моделей, кэша нейросетей, файлов накладных и локальных индексов баз данных из репозитория.
